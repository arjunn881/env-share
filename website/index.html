The problem

Your secrets deserve better
than a Slack message.

Every day, developers copy-paste .env files into chat apps, emails, and shared notes. Those secrets live in logs and history forever.

The old way — dangerous
  • Secrets visible in Slack, Discord, email history indefinitely
  • Workspace admins, bots, and future breaches can access them
  • No expiry — shared secrets sit around forever
  • Easy to accidentally commit to git if re-shared as a file
share-env — secure by design
  • AES-256-GCM encrypted before leaving your machine
  • Relay server sees only ciphertext — never the key
  • Auto-expires after 10 minutes, deleted on first pull
  • Blocks the tool if .gitignore doesn't protect .env

How it works

Zero-knowledge relay in three steps.

The decryption key travels exclusively inside the share code — the relay server is completely blind to it.

  • 3Encrypt .env with AES-256-GCM
  • 4POST ciphertext + IV + auth tag to relay
  • 5Build share code: phrase#hexKey
  • 6Send code via Slack / Teams / Signal

Features

Built with security non-negotiable.

Zero-Knowledge Encryption
AES-256-GCM key is generated locally and never transmitted. Even full relay compromise yields only unreadable ciphertext.
Burn-After-Reading
Payload is permanently deleted from the relay the moment it is pulled. It cannot be retrieved a second time by anyone.
Smart Merge
If you already have a .env, the tool detects conflicts key-by-key and interactively asks you to choose local or remote.
Git Guardrails
Refuses to run unless your .gitignore explicitly ignores .env and .env.* files. Prevents accidental secret commits.
Zero Setup
No global install, no accounts, no config. Run via npx share-env. Requires only Node.js 18+. Works instantly out of the box.
10-Minute TTL
Share codes expire automatically after 10 minutes. Uncollected payloads are permanently purged from the relay — nothing lingers.

Installation
No installation required. Run directly with npx. The package is fetched and executed on demand. You need Node.js 18+ installed.
bash
# No global install needed $ npx share-env --help # Optional: install globally for frequent use $ npm install -g share-env
Prerequisites: Your project must have a .gitignore file that explicitly ignores .env and .env.*. The tool will refuse to run otherwise.
push

Reads your .env file, validates it, encrypts it locally with AES-256-GCM, and uploads only the ciphertext to the relay server. Returns a one-time share code.

usage
$ npx share-env push [options]
OptionTypeDefaultDescription
-f, --file <path>string.envPath to the .env file to encrypt and share
--server <url>stringenv-share-1rsi.onrender.comOverride the relay server base URL
examples
# Share default .env $ npx share-env push # Share a specific env file $ npx share-env push --file ./config/.env.production # Use a self-hosted relay $ npx share-env push --server https://your-relay.example.com
output
3 key(s) loaded from .env Encrypted payload stored on relay. Payload uploaded. Your share code: +--------------------------------------------------+ | apple-brave-cloud#a3f9b2c1d4e5f6a7b8c9d0e1f2... | +--------------------------------------------------+ Send the code above to your teammate. It expires in 10 minutes. One-time use only.
pull

Fetches the encrypted payload from the relay using the phrase, decrypts it locally using the key in the share code, and merges it into your local .env.

usage
$ npx share-env pull <share-code> [options]

# Pull into default .env $ npx share-env pull apple-brave-cloud#a3f9b2c1... # Pull into a specific path $ npx share-env pull apple-brave-cloud#a3f9b2c1... --file ./config/.env.local # With a self-hosted relay $ npx share-env pull apple-brave-cloud#a3f9b2c1... --server https://your-relay.example.com

Security

Designed to be paranoid.

The relay server is architecturally blind. Even if it were fully compromised, an attacker would have only unreadable ciphertext.

Encryption flow (local)
1
Key generation. crypto.randomBytes(32) generates a 256-bit key. It lives only in local memory — never written to disk.
2
IV generation. crypto.randomBytes(12) generates a 96-bit Initialization Vector, making ciphertext unique even for identical inputs.
3
AES-256-GCM encryption. Produces ciphertext + a 128-bit authentication tag. Any tampering with the ciphertext is detected and rejected at decryption time.
4
Network upload. Only ciphertext, IV, and auth tag are sent to the relay. The 256-bit key never leaves your machine.
5
Share code construction. phrase#hexKey — the phrase is the relay lookup ID, the key is the 64-char hex decryption key. Both are required.
Threat model
ThreatMitigation
Relay server breachedOnly ciphertext stored — no key, no decryption. Mitigated
Share code interceptedTreat it like a password. Use encrypted channels. User risk
Wrong person pulls firstPayload deleted on first pull. Requester can re-push. Mitigated
Payload left uncollectedAuto-deleted after 10-minute TTL. Mitigated
Accidental git commitTool refuses to run if .gitignore doesn't cover .env. Mitigated
Ciphertext tamperedGCM auth tag verification fails and rejects silently. Mitigated
What the relay sees: Ciphertext, IV, and auth tag only. The 64-character hex decryption key is never transmitted — it travels exclusively inside the share code you send manually.

Error Reference

Know what every error means.

Complete reference for all errors, their root causes, and how to fix them.

FATAL Your .gitignore does not ignore .env files

Your project's .gitignore file either does not exist or does not contain rules to ignore .env and .env.*. This check is deliberate — it prevents accidental secret commits. Both sender and receiver must pass this check.

  • No .gitignore file exists in the project root
  • .gitignore exists but is missing the .env entry
fix — add to .gitignore
# Add these two lines to your .gitignore .env .env.*
FATAL Your .env file contains malformed lines

One or more lines in your .env file do not follow the required KEY=VALUE format. Comment lines (starting with #) and blank lines are allowed. Lines without an = separator are not.

  • A line exists without an = character (e.g. a stray word or incomplete entry)
  • Trailing commas or semicolons that break the parser
valid .env format
# Comments are fine DATABASE_URL=postgres://localhost:5432/mydb API_KEY=your_api_key_here DEBUG=true # Blank lines are fine too SECRET_TOKEN=abc123xyz
NOT FOUND The phrase was not found on the relay server

The share code's identifier does not match any active payload on the relay server. This is returned as a 404.

  • The payload was already pulled by someone (burn-after-reading)
  • The 10-minute TTL expired before the pull
  • The share code was truncated or copied incorrectly

Fix: Ask the sender to run npx share-env push again and generate a fresh share code.

FATAL DECRYPTION FAILED

The AES-256-GCM authentication tag verification failed during decryption. This means the key is wrong, the ciphertext was tampered with, or the share code was truncated.

  • The key portion (after #) was truncated when copying — it must be exactly 64 hex characters
  • The share code was modified in transit (e.g. a chat app wrapped it)
  • The ciphertext was tampered with on the relay (GCM detects this)

Fix: Ask the sender to re-push and share the complete, unmodified share code. Ensure no chat app is auto-linking or wrapping the code.

429 Too many requests — rate limited

The relay server enforces a rate limit of 10 requests per minute per IP address to prevent abuse. This error is returned with a 429 HTTP status.

  • You ran push or pull more than 10 times in under a minute
  • Multiple team members pushing simultaneously from the same NAT IP

Fix: Wait 60 seconds and retry. For teams with high volume, self-host the relay and increase RATE_LIMIT_MAX.

Self-Hosting

Full control over your relay.

The relay is open source. Deploy it on Render, Railway, Fly.io, or any VPS. The CLI's --server flag points to yours.

1
Clone the repository
Clone the env-share monorepo and navigate to it.
bash
$ git clone https://github.com/arjunn881/env-share.git $ cd env-share
2
Install and build
Install all workspace dependencies and compile both TypeScript packages.
bash
$ npm install $ npm run build
3
Start the relay server
Start the relay. Default port is 3000. Override with the PORT env var.
bash
$ npm start --workspace=server # custom port: $ PORT=8080 npm start --workspace=server
4
Point your CLI at it
Use the --server flag on both push and pull.
bash
$ npx share-env push --server https://relay.myteam.com $ npx share-env pull <code> --server https://relay.myteam.com
Server configuration
VariableDefaultDescription
TTL_SECONDS600Seconds before uncollected payloads are auto-deleted
RATE_LIMIT_MAX10Max requests per minute per IP address
PORT3000Port the server listens on (set via env var)
Recommended platforms: Render (free tier), Railway, Fly.io, or any VPS running Node.js 18+. The relay is stateless in-memory — no database required.
Note: Self-hosted relay config lives in server/src/index.ts. Restart the server after changing TTL_SECONDS or RATE_LIMIT_MAX.
